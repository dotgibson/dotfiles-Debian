# dotfiles-Debian :: base CLI stack (apt / Debian-family names)
# ──────────────────────────────────────────────────────────────────────────────
# One package per line. '#' comments and blank lines are ignored (blib_read_pkgs).
# Target: Ubuntu 24.04 LTS (noble). Also resolves on Debian trixie — both are CI lanes.
#
# THIS LIST IS DELIBERATELY SHORTER THAN THE OTHER LINUX REPOS'.
# Ubuntu 24.04 froze in April 2024, so a large slice of the modern-CLI stack is either
# absent from noble or too old to satisfy Core. Everything apt cannot honestly supply
# lives in bootstrap.sh as a pinned, SHA-256-verified release asset instead — see
# install/tool-versions.env. A name only belongs HERE if apt really resolves it at a
# version Core can use; listing anything else just moves the failure to first-boot,
# where apt_install's per-package retry hides it behind a "skipped" line.
#
# Binary renames: `bat` runs as `batcat` and `fd-find` installs `fdfind` — Core's
# 00-tools.zsh already resolves both, and 20-aliases.zsh aliases them back. Don't
# "fix" that here.
#
# `# min:X.Y.Z` trailing comments are a CONTRACT, not prose: test/check-packages.sh
# compares the apt candidate against them with `dpkg --compare-versions`. Name
# resolution alone is not enough on a frozen archive — neovim 0.9.5 and
# tree-sitter-cli 0.20.8 both resolve fine and both break the box.
#
# `# only:<ids>` / `# skip:<ids>` are the DISTRO TIER, read by scripts/pkg-filter.sh
# and applied before blib_read_pkgs. IDs are /etc/os-release ID values, comma-separated,
# no spaces: ubuntu, debian, kali. An unannotated line applies everywhere, so the
# untiered majority of this file reads exactly as it always did.
#
# The tier exists because the three targets do not share an archive age. Ubuntu 24.04
# froze in April 2024; Kali is a rolling sid derivative. A dozen tools this repo must
# fetch out-of-band on noble are simply in apt on Kali, and installing them twice — once
# as a pinned tarball, once from apt — would be worse than either alone. bootstrap.sh's
# verified_install and vendor-repo steps carry the mirror image of these annotations.
# ──────────────────────────────────────────────────────────────────────────────

# ── rolling-only: in apt on Kali, out-of-band everywhere else ─
# Every name below is absent from noble (or present too old to satisfy Core), so on
# ubuntu/debian bootstrap.sh installs it as a pinned SHA-256'd release asset, a
# `go install`, or from a vendor apt repo. Kali's archive tracks sid and simply has
# them, so there the distro build wins: fewer moving parts, and apt owns the upgrade.
#
# Provenance: this set is exactly dotfiles-Offense's former base list minus what this
# repo already had — proven resolvable by that repo's own kali-rolling packages lane
# before the OS-native layer moved here.
#
# The `# min:` floors ARE repeated here, and that is the whole reason this tier is safe.
# A floor is a statement about what CORE needs, not about how old an archive is: nvim
# below 0.12 breaks Core's pinned nvim-treesitter whether it came from a frozen suite or
# a rolling one. Tiering a package in without its floor would silently swap a pinned,
# known-good 0.12.4 for whatever apt happens to have — a DOWNGRADE dressed as a
# simplification. test/check-packages.sh applies the same tier as bootstrap.sh, so the
# kali lane checks these floors on kali and nowhere else.
neovim                 # only:kali  min:0.12.0  — Core's nvim-treesitter hard-requires
                       #             0.12; pinned NVIM_VERSION on ubuntu/debian
tree-sitter-cli        # only:kali  min:0.26.1  — nvim-treesitter's floor (core's
                       #             PORTING-MATRIX footnote 5); no Debian/Ubuntu suite
                       #             short of sid clears it, which is why Kali can
starship               # only:kali   pinned STARSHIP_VERSION elsewhere
lazygit                # only:kali   pinned LAZYGIT_VERSION elsewhere
procs                  # only:kali   pinned PROCS_VERSION elsewhere
xh                     # only:kali   pinned XH_VERSION elsewhere
du-dust                # only:kali   binary stays `dust`; pinned DUST_VERSION elsewhere
difftastic             # only:kali   binary: difft; pinned DIFFT_VERSION elsewhere
yq-go                  # only:kali   mikefarah's Go yq. NOT plain `yq`, which is
                       #             kislyuk's Python one — installing that is worse
                       #             than installing none. `go install`ed elsewhere.
glow                   # only:kali   Charm's signed vendor repo elsewhere
gum                    # only:kali   Charm's signed vendor repo elsewhere
cargo                  # only:kali   noble's rustc 1.75 is too old to build yazi /
                       #             ast-grep / viddy, so this repo skips all three
                       #             there and Core HAVE_*-gates them. Kali's rustc
                       #             builds them, so the toolchain is worth having.
python3-pynvim         # only:kali   nvim's python provider
wl-clipboard           # only:kali   see "Deliberately NOT here" below — the headless
xclip                  # only:kali   rule is an ubuntu/debian fact, not a family one.
                       #             Kali runs under WSL2 with WSLg (and on bare metal),
                       #             where a clipboard backend has something to talk to.
#

#   wl-clipboard / xclip — on ubuntu/debian only: headless, ssh-only, no display for

#   flatpak / snapd      — no GUI apps on these boxes. snapd is left exactly as Ubuntu
#     shipped it: removing it is a system-policy call, not a dotfiles one.
